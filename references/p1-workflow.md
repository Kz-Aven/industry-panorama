# 工作行为匹配与批量导出

## 从动作选择图形

先从资料提取人物、动作、工具和工作对象，再输入各自的词组。P1 使用可审计的词组规则，要求四个字段同时命中。同一个角色做不同动作时可命中不同规则。结果含规则 ID、每个字段的命中词、对应的资产 ID、建议姿态及四向旋转。带 `placement` 时，朝向按人物与焦点坐标的主轴选择。

```sh
npm run scene -- assets match examples/p1/warehouse-action.json
```

`unmatched`、`ambiguous` 或 `missing-assets` 返回退出码 2。无匹配时回看源材料，再手工查找等价资产或提登记草稿。已在图中验收的映射可写入 [工作行为规则](../config/action-assets.json)。按行业限定的规则优先于通用规则。同优先级命中多条时在清单里消除歧义。建议姿态对应资产的现有姿势，实际动作还要用场景对象及其位置表达。

八种模板的槽位可以在 [templates](../templates) 查看。新样例分别使用仓储出货、会议评审、客户接待和监控中心，场景物件直接引用各模板的命名槽位。

## 一次验收多个场景

先把原始资料转换成 Scene/Atlas JSON。每份输入对应一个任务，可指定 html、svg、png 或 plan。任务输入相对批次清单所在目录，输出为目标目录中的文件名。成功文件和逐任务报告都写入指定目录。报告包含任务输入、成功产物、缺失素材 ID 与场景 ID，或发现布局错误的场景 ID 和错误说明。

```sh
npm run scene -- batch examples/p1/batch.json -o outputs/p1
```

部分输入失败时，完整图谱任务会报告其所有失败场景，其他任务继续完成。修复后可重跑同一批次。HTML 导出保持单文件和离线，重复的 PNG/SVG 数据在文件中只存一份，画布按需加载可见或已选场景。浏览器需要启用 JavaScript。

两张专项图谱的案例来源分别为案例库中的《客户工单回复与进度通知》和《来料跟催》。医疗问诊是自编的行为与布局示意，聚焦主诉和资料记录。试读时请读者先看画面及卡片，不读侧栏详细说明，再按自然语言复述每一步谁在做什么、下一步接到什么、哪些判断要交还给人。
