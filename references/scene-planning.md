# 布局与语义

## 知识到图形

每个动作至少回答「谁对什么做了什么」，资料提供结果时再补产出。让人物朝向目标，放在操控面或工作台边。机台、单据和样品是动作线索。维修用人员、异常机台和工具车组合。排产用计划员、排产看板、工单和协作对象组合。AI 机会图用系统界面、待办与确认动作体现数字角色的工作，将操作者、输入、人工确认和执行权限记录于详情。

| 输入 | 核心叙事 |
| --- | --- |
| 行业研究 | 沿环节或职能分区，保留原分类与环节证据 |
| 岗位说明 | 按工作情境分场，表现岗位、协作者、工具和工作结果 |
| 流程或对象 | 按同一订单、客户、批次或物料经过的状态分场 |
| 单场景 | 用一个平台突出主要动作，环境物件只承担明确作用 |
| AI 落地案例 | 用任务、工作台与数据表达输入、产出和岗位协作 |

## 坐标与模板

| 模板 | 默认底板 | 用途 |
| --- | --- | --- |
| `single-workstation` | 9 × 6 | 单人办公室、审核工位 |
| `team-collaboration` | 10 × 7 | 两人以上协作、评审 |
| `production-line` | 13 × 8 | 线性设备、输送和检测 |
| `equipment-operation` | 9 × 7 | 单设备操作、维修、检测 |

模板只提供槽位和参考尺寸。底板范围由场景指定，横向为 x，纵向为 y，地板顶面 z=0。物体坐标是占地中心，旋转 0、90、180、270 度时同时变换绘制素材和占地宽深。显式 `position: [x,y,0]` 或 `slot` 二选一，省略时用物体 ID 查同名槽位。桌面纸件或设备配件指定 `support` 为承托对象 ID。坐标仍使用全局 x、y，用注册表的 `surface_height` 计算 z；俯视范围必须在支撑区域之内。不要用缩放来躲避碰撞。

## 保留引用

- `source_refs` 保存原资料标题和可重定位路径，如锚点、数据块、章节或案例行 ID。案例中的原句保存在案例详情里。用户描述可用本次需求及相应段落作为来源。
- 每个场景内部独立维护角色、对象、动作、物体 ID。动作指向角色及业务对象，物体的 `target` 指向另一个实体物体。用户已有案例 ID 可加稳定命名空间并保留原号。
- Scene 的 `interaction.case_ids` 决定详情顺序。物体的同名字段提供详情里的案例快捷入口。对象的 `source_refs` 引用 Scene 或 Atlas 已定义的来源。分区顺序决定场景阅读顺序。
- 已有 HTML 的岗位协作、逻辑链、业务对象可用 Atlas 的 `layers` 按原次序保留，字段放到 `sections.entries`。使用来源确认链接的业务语义。
